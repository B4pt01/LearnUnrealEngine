Enhanced Input & personnage

Un jeu commence par un personnage qui répond bien aux commandes. Ce chapitre explique le système d'entrées d'UE5, Enhanced Input, puis construit pas à pas un personnage complet en C++ : déplacement, caméra, saut et sprint. Vous verrez aussi comment régler le Character Movement Component et choisir un style de caméra.

Dans ce chapitre

  • Comprendre les Input Actions, Mapping Contexts, Triggers et Modifiers
  • Savoir quel événement (Started, Triggered, Completed…) écouter
  • Écrire un personnage à la troisième personne complet en C++ et en Blueprint
  • Régler le Character Movement Component et ses modes de déplacement
  • Choisir et configurer une caméra : troisième personne, première personne, vue du dessus

Enhanced Input : les concepts

L'ancien système (Action Mappings et Axis Mappings dans les Project Settings) est remplacé dans UE5 par Enhanced Input, activé par défaut dans les nouveaux projets. Son idée centrale : séparer ce que le joueur veut faire (sauter, se déplacer) de la touche qui le déclenche (barre d'espace, bouton A de la manette). Quatre notions à connaître :

Input Action
Un asset qui représente une intention du joueur : IA_Jump, IA_Move. Il définit le type de valeur produite. Votre code n'écoute que des Input Actions, jamais des touches.
Input Mapping Context
Un asset qui associe des touches à des Input Actions : IMC_Default dit « Espace et bouton A déclenchent IA_Jump ». On peut en activer plusieurs à la fois, avec des priorités.
Modifier
Transforme la valeur brute d'une touche : inverser un axe, ignorer les petites valeurs d'un stick, multiplier la sensibilité.
Trigger
Décide quand l'action se déclenche : dès l'appui, au relâchement, après un maintien de 0,5 seconde, sur un double appui…

Les types de valeur

Value TypeType C++Exemples
Digital (bool)boolSauter, tirer, interagir, ouvrir le menu
Axis1D (float)floatAccélérateur d'une voiture, molette de zoom
Axis2D (Vector2D)FVector2DDéplacement (avant/côté), regard (souris, stick droit)
Axis3D (Vector)FVectorVol libre (avant, côté, haut), contrôleurs à six axes

Les Mapping Contexts

Un contexte regroupe les commandes valables dans une situation. Le personnage à pied utilise IMC_Default ; en montant dans un véhicule, on retire ce contexte et on ajoute IMC_Vehicle ; en ouvrant un menu, on ajoute IMC_Menu par-dessus. La priorité (un entier) départage deux contextes qui utilisent la même touche : le plus prioritaire consomme l'entrée.

Les événements ETriggerEvent

À chaque frame, l'action passe par un état, et les transitions entre états produisent des événements que vous pouvez écouter :

ÉvénementSignification
StartedPremière frame où la touche est actionnée (le trigger commence à évaluer)
OngoingLe trigger est en cours d'évaluation mais pas encore satisfait (pendant un Hold, par exemple)
TriggeredLe trigger est satisfait : c'est l'événement principal, éventuellement à chaque frame
CompletedL'action s'arrête après avoir été déclenchée (touche relâchée)
CanceledL'évaluation s'est arrêtée sans jamais déclencher (Hold relâché trop tôt)

Quel événement écouter ?

Déplacement et regard : Triggered (à chaque frame). Saut : Started pour Jump et Completed pour StopJumping (la hauteur dépend de la durée d'appui). Sprint ou visée maintenus : Started et Completed. Action ponctuelle avec un trigger Pressed ou Hold : Triggered.

Du clavier vers un Axis2D

IA_Move produit un FVector2D : X pour le côté (droite positive), Y pour l'avant. Une touche de clavier, elle, ne produit qu'une valeur 1D (1 quand elle est enfoncée), placée sur l'axe X. Les modifiers la déplacent sur le bon axe avec le bon signe :

ToucheModifiersValeur obtenuePourquoi
W (avancer)Swizzle Input Axis Values (YXZ)(0, 1)La valeur passe de X à Y
S (reculer)Swizzle (YXZ) + Negate(0, -1)Sur Y, puis inversée
D (droite)Aucun(1, 0)Déjà sur X, positive
A (gauche)Negate(-1, 0)Sur X, inversée
Gamepad Left Thumbstick 2D-AxisDead Zone(x, y) continuLe stick fournit déjà les deux axes
Mouse XY 2D-Axis (pour IA_Look)Negate sur Y seulement (comme le template)(dx, dy)Ajuste le sens vertical du regard

Quand deux touches sont enfoncées (W + D), Enhanced Input additionne leurs valeurs : on obtient (1, 1). Le Character Movement Component limite de toute façon la vitesse, donc on ne va pas plus vite en diagonale.

Claviers AZERTY

Les touches de lettres sont identifiées par la lettre qu'elles portent, pas par leur position : sur un clavier AZERTY, W et A ne tombent pas sous la main gauche. Ajoutez des mappings Z et Q en plus de W et A, ou proposez le remappage des touches (voir plus bas). Vérifiez toujours avec la disposition de clavier de vos joueurs.

Mise en place pas à pas

  1. Vérifier le pluginLe plugin Enhanced Input est activé par défaut dans les projets UE5 récents (Edit → Plugins pour le vérifier).
  2. Déclarer le moduleAjoutez "EnhancedInput" aux dépendances de MyGame.Build.cs (voir C++ pour Unreal).
  3. Classes par défautDans Project Settings → Engine → Input, section Default Classes : Default Player Input Class = EnhancedPlayerInput et Default Input Component Class = EnhancedInputComponent (valeurs par défaut des projets récents). Elles sont stockées dans DefaultInput.ini :
  4. Créer les Input ActionsDans le Content Browser : clic droit → Input → Input Action. Créez IA_Move et IA_Look (Value Type : Axis2D), IA_Jump et IA_Sprint (Digital).
  5. Créer le Mapping ContextClic droit → Input → Input Mapping Context : IMC_Default. Ajoutez une ligne par action, puis les touches et modifiers du tableau précédent ; Space et Gamepad Face Button Bottom pour IA_Jump, Left Shift pour IA_Sprint.
  6. Brancher les assetsDans le Blueprint du personnage (enfant de la classe C++ ci-dessous), renseignez Default Mapping Context et chaque Input Action dans la catégorie Input du panneau Details.

Pourquoi NotifyControllerChanged et pas BeginPlay ?

Quand un personnage réapparaît en cours de partie, son BeginPlay s'exécute pendant le spawn, avant que le PlayerController ne le possède : GetController() est encore nul et le contexte n'est jamais ajouté. NotifyControllerChanged est appelée à chaque changement de contrôleur, donc au bon moment. C'est l'approche des templates récents ; ajouter le contexte dans le BeginPlay du PlayerController est une autre solution courante.

Sprint et multijoueur

Changer MaxWalkSpeed uniquement sur le client fonctionne en solo, mais en réseau le serveur, qui ignore le sprint, corrige sans cesse la position du joueur (saccades). Il faut faire passer l'information au serveur, idéalement via les mécanismes de prédiction du Character Movement Component. Voir Réseau & multijoueur.

Pawn ou PlayerController ?

Les entrées peuvent être liées dans le Pawn (SetupPlayerInputComponent) ou dans le PlayerController (SetupInputComponent). La règle : ce qui dépend du corps va dans le Pawn, ce qui doit fonctionner même sans corps va dans le PlayerController.

Dans le Pawn / Character

  • Se déplacer, sauter, s'accroupir
  • Tirer, recharger l'arme tenue
  • Commandes propres à un véhicule (dans le Pawn véhicule)

Dans le PlayerController

  • Menu pause, tableau des scores, chat
  • Carte du monde, inventaire global
  • Tout ce qui doit marcher pendant la mort ou en spectateur

Le Character Movement Component

Le UCharacterMovementComponent (CMC) est l'un des composants les plus riches du moteur : marche sur les pentes, marches d'escalier, saut, chute, nage, vol, plateformes mobiles, et prédiction réseau. Ses réglages se trouvent dans le panneau Details du composant Character Movement. Les principaux :

Les valeurs par défaut sont celles du composant ; les templates d'Epic en changent plusieurs (le Third Person utilise par exemple JumpZVelocity = 700 et AirControl = 0.35).

Les modes de déplacement

Le CMC fonctionne comme une machine à états : à chaque instant, le personnage est dans un mode de déplacement (EMovementMode) qui détermine la physique appliquée.

La caméra

Control Rotation et rotation du Pawn

Deux rotations coexistent et il est essentiel de ne pas les confondre. La Control Rotation appartient au Controller : c'est la direction dans laquelle le joueur regarde (modifiée par la souris ou le stick droit). La rotation du Pawn est l'orientation de son corps. Des options décident si l'une copie l'autre.

Manette, mobile et remappage

  • Manette : ajoutez simplement les touches de manette dans le même Mapping Context (Gamepad Left Thumbstick 2D-Axis avec Dead Zone, Gamepad Face Button Bottom…). Vos Input Actions et votre code ne changent pas : c'est tout l'intérêt d'Enhanced Input.
  • Mobile : les joysticks virtuels (Touch Interface, réglable dans Project Settings → Input) produisent des valeurs de sticks de manette, donc les mêmes mappings fonctionnent. Les écrans tactiles exposent aussi des touches Touch. Les options exactes varient selon votre version du moteur.
  • Remappage par le joueur : les versions récentes d'UE5 proposent les Enhanced Input User Settings (à activer dans Project Settings → Engine → Enhanced Input). On marque les mappings comme remappables (Player Mappable Key Settings), puis on modifie et sauvegarde les touches via UEnhancedInputUserSettings. Cette API a évolué entre les versions et a longtemps été marquée expérimentale : suivez la documentation de votre version, et inspirez-vous du projet Lyra.

Sur quel ETriggerEvent lier la fonction Move d'un personnage pour qu'il avance tant que la touche est enfoncée ?

  • Started
  • Triggered
  • Completed
  • Ongoing

Sans trigger particulier, l'action est déclenchée à chaque frame tant que la touche est actionnée : Triggered arrive donc en continu. Started n'arrive qu'une fois, au premier appui.

Une action « fouiller » utilise un trigger Hold de 1 seconde. Le joueur relâche la touche après 0,4 seconde. Quel événement reçoit-il en dernier ?

  • Triggered
  • Completed
  • Canceled
  • Aucun événement

Le trigger a commencé à évaluer (Started, puis Ongoing) mais n'a jamais été satisfait : son interruption produit Canceled. Completed ne suit qu'une action réellement déclenchée.

Dans un jeu à la troisième personne, la caméra tourne bien avec la souris, mais le personnage reste toujours orienté face à la caméra, même en marchant de côté. Que faut-il changer ?

  • Mettre bUsePawnControlRotation à true sur la caméra
  • Mettre bUseControllerRotationYaw à false et bOrientRotationToMovement à true
  • Augmenter RotationRate
  • Ajouter un modifier Negate sur IA_Look

Avec bUseControllerRotationYaw, le Pawn copie le yaw de la Control Rotation. Pour un personnage qui se tourne vers sa direction de marche, il faut le désactiver et laisser le CMC orienter le corps (bOrientRotationToMovement).

Une esquive rapide (dash)

Ajoutez au personnage une action IA_Dash (Digital, trigger Pressed, touche Left Alt et bouton droit de la manette). Le dash propulse le personnage dans la direction de son déplacement (ou devant lui s'il est immobile), puis n'est plus utilisable pendant une seconde. Exposez la force et le temps de recharge aux designers, et un événement Blueprint OnDash pour l'effet visuel.

Voir la solution

Au sol, le freinage et la friction réduisent vite l'élan : si le dash vous semble court, augmentez DashStrength ou baissez temporairement GroundFriction pendant le dash. Pour afficher la recharge dans l'interface, une fonction BlueprintPure peut renvoyer GetWorldTimerManager().GetTimerRemaining(DashCooldownHandle).

À retenir

  • Input Action = intention, Mapping Context = touches, Modifiers = transformation de la valeur, Triggers = moment du déclenchement.
  • Triggered pour le continu, Started/Completed pour le maintien ; Canceled si un trigger échoue.
  • Ajoutez le contexte via UEnhancedInputLocalPlayerSubsystem et liez les actions dans SetupPlayerInputComponent avec BindAction.
  • AddMovementInput exprime une intention ; le Character Movement Component applique accélération, friction et collisions.
  • Control Rotation (regard) et rotation du Pawn (corps) sont distinctes ; trois options décident qui suit qui.
  • Le corps dans le Pawn, ce qui doit survivre à la mort dans le PlayerController.
