Ressources & glossaire

Ce guide vous a donné les fondations. Pour aller plus loin, il faut savoir où chercher : la documentation d'Epic, le code source du moteur, les projets d'exemple, les communautés. Ce dernier chapitre rassemble les meilleures ressources, une méthode pour débloquer un problème seul, un glossaire de tous les termes rencontrés et une checklist pour mesurer votre progression.

Lire la référence d'un nœud depuis l'éditeur

Survolez un nœud Blueprint : l'info-bulle affiche sa description, tirée des commentaires du code C++. Avec un IDE configuré, double-cliquer sur un nœud implémenté en C++ ouvre sa définition dans le code source : le moyen le plus rapide de voir ce qu'il fait vraiment.

Le code source : la documentation ultime

Unreal Engine est livré avec son code source complet. Quand la documentation est muette, le code dit toujours la vérité. Depuis votre IDE, Aller à la définition (F12 dans Visual Studio, Ctrl + clic dans Rider) sur UGameplayStatics::ApplyDamage vous montre exactement ce que fait la fonction. Les commentaires des en-têtes sont souvent plus complets que la documentation en ligne.

Pour consulter le code sans IDE, le dépôt EpicGames/UnrealEngine sur GitHub est accessible après avoir lié votre compte Epic à votre compte GitHub (procédure décrite dans Installation & premier projet). Sa recherche de code permet de trouver en quelques secondes tous les usages d'une fonction dans le moteur : d'excellents exemples d'utilisation.

Lyra n'est pas un projet de débutant

Lyra est souvent recommandé, mais son architecture (plugins Game Features, expériences, GAS partout) est conçue pour une grande équipe. Le lire trop tôt décourage. Revenez-y quand vous maîtrisez les chapitres C++ et Systèmes de gameplay, et commencez par un seul système (par exemple l'équipement ou les réglages).

Se débloquer seul

Être bloqué fait partie du métier. Ce qui distingue un développeur expérimenté, c'est sa méthode pour se débloquer :

Une reproduction minimale ressemble à ceci : un niveau vide, un seul Blueprint, trois nœuds qui montrent le comportement inattendu. Si le problème disparaît dans le niveau vide, il vient de ce que vous avez retiré : c'est déjà une piste.

Une question qui restera sans réponse

« Mon personnage marche pas, help !!! »

Une question qui obtiendra une réponse

« UE 5.4, C++. Mon ACharacter ne bouge pas : Move() est bien appelé (log), AddMovementInput reçoit (1, 0, 0), mais la vitesse reste à 0. Le Mapping Context est ajouté dans BeginPlay. Code et capture du composant ci-joints. Reproduit dans un projet Third Person vierge. »

Indiquez toujours la version du moteur, Blueprint ou C++, ce que vous attendiez, ce qui se passe, ce que vous avez déjà essayé, et joignez le code (en texte, pas en photo d'écran) ou une capture lisible du graphe.

Un bug n'apparaît que dans votre grand niveau, pas dans un niveau de test vide contenant le même personnage. Qu'en déduisez-vous ?

  • C'est un bug du moteur, il faut le signaler à Epic
  • La cause est dans quelque chose que le grand niveau contient et pas le niveau de test : ajoutez-y les éléments un par un pour la trouver
  • Il faut recompiler le moteur depuis les sources
  • Le niveau de test est inutile

C'est tout l'intérêt de la réduction : la différence entre le cas qui marche et celui qui ne marche pas contient la cause. On procède par dichotomie : ajouter ou retirer la moitié des éléments à chaque essai.

Glossaire

Les termes rencontrés dans ce guide, avec leur nom anglais et le chapitre où ils sont expliqués. Astuce : la recherche du site (Ctrl + K) trouve aussi les sections de cette page.

A – C

Actor
Tout objet qui peut être placé ou créé dans un niveau (AActor). Voir Architecture.
Actor Component
Un morceau de comportement réutilisable attaché à un Actor (UActorComponent) ; un Scene Component a en plus une position.
AIController
Le « cerveau » d'un Pawn contrôlé par l'IA. Voir Intelligence artificielle.
Anim Notify
Un événement placé sur une frame d'animation (bruit de pas, coup qui touche). Voir Animation.
Asset
Un fichier de contenu du projet (.uasset) : mesh, texture, son, Blueprint…
Autorité (Authority)
En réseau, la machine qui fait foi pour un Actor, en général le serveur. Voir Réseau & multijoueur.
Behavior Tree
Un arbre de décision pour l'IA, lu par un AIController avec un Blackboard.
BeginPlay
L'événement appelé quand un Actor commence à exister dans la partie.
Blackboard
La mémoire d'une IA : des clés (cible, position) lues par le Behavior Tree.
Blend Space
Un asset qui mélange des animations selon des paramètres (vitesse, direction).
Blueprint
Le système de scripting visuel, et par extension une classe créée avec. Voir Blueprints.
Build.cs
Le fichier qui décrit un module C++ et ses dépendances. Voir C++ : les bases.
Cast
La conversion d'une référence vers un type plus précis, qui échoue si l'objet n'est pas de ce type.
CDO (Class Default Object)
L'objet « modèle » d'une classe, qui contient ses valeurs par défaut.
Channel (canal de collision)
Une catégorie de collision (Visibility, Camera, Pawn…) à laquelle chaque objet répond Ignore, Overlap ou Block. Voir Collisions.
Character Movement Component
Le composant qui gère marche, saut, chute, nage et vol d'un ACharacter.
Construction Script
Le graphe d'un Blueprint exécuté dans l'éditeur à chaque modification de l'Actor.
Cook
La conversion des assets dans le format de la plateforme cible avant le packaging. Voir Packaging.
CVar (Console Variable)
Un réglage modifiable depuis la console ou les fichiers .ini (r.ScreenPercentage).

D – H

Data Asset / Data Table
Des assets qui contiennent des données (statistiques d'objets, de niveaux) plutôt que de la logique. Voir Systèmes de gameplay.
Delegate
Une référence vers une ou plusieurs fonctions à appeler plus tard ; l'Event Dispatcher en est la version Blueprint. Voir C++ avancé.
DeltaTime (Delta Seconds)
Le temps écoulé depuis la frame précédente, en secondes. Toute vitesse doit être multipliée par lui.
Dot product (produit scalaire)
Un nombre qui mesure à quel point deux directions sont alignées. Voir Maths.
Enhanced Input
Le système d'entrées d'UE5 : Input Actions et Mapping Contexts. Voir Enhanced Input.
EQS (Environment Query System)
Un système qui note des points ou des Actors pour qu'une IA choisisse le meilleur (couverture, fuite).
Event Dispatcher
Un événement auquel d'autres Blueprints s'abonnent ; l'émetteur ignore qui l'écoute.
Frame
Une image calculée et affichée : un tour de la boucle de jeu.
GameInstance
L'objet qui existe pendant toute la durée du jeu, d'un niveau à l'autre.
GameMode
Les règles de la partie (classes par défaut, conditions de victoire), uniquement sur le serveur.
GameState / PlayerState
L'état de la partie et l'état de chaque joueur, répliqués à tous les clients.
Gameplay Ability System (GAS)
Un framework de capacités, attributs et effets, utilisé par Lyra et Fortnite.
Gameplay Tag
Une étiquette hiérarchique (State.Stunned) pour décrire et interroger des états.
Garbage Collector (GC)
Le système qui libère automatiquement les UObjects qui ne sont plus référencés.
GENERATED_BODY
La macro qui insère le code généré par l'Unreal Header Tool dans une classe C++.
Gimbal lock (blocage de cardan)
La perte d'un axe de rotation avec les angles d'Euler, évitée par les quaternions.
HUD
L'affichage tête haute : informations à l'écran pendant le jeu. Voir Interfaces avec UMG.
Hit / Overlap
Les deux réponses de collision : bloquer (et générer un Hit) ou traverser (et générer un Overlap).

I – N

Instance
Un objet créé à partir d'une classe ; chaque orbe du niveau est une instance de BP_Orb.
Interface
Un ensemble de fonctions que plusieurs classes sans lien peuvent implémenter.
Level / Map
Un niveau : un fichier .umap qui contient des Actors.
Lerp
L'interpolation linéaire entre deux valeurs selon un Alpha de 0 à 1.
Live Coding
La recompilation du C++ pendant que l'éditeur tourne (Ctrl + Alt + F11).
LOD (Level of Detail)
Des versions simplifiées d'un mesh affichées de loin.
Lumen
Le système d'éclairage global et de réflexions dynamiques d'UE5. Voir Graphismes.
Material / Material Instance
Le shader qui décrit l'apparence d'une surface, et sa variante paramétrée sans recompilation.
MetaSound
Un graphe de génération audio procédurale. Voir Audio.
Montage
Un asset d'animation joué à la demande (attaque, rechargement), avec sections et notifies.
NavMesh
Le maillage de navigation qui indique où l'IA peut marcher.
Nanite
La géométrie virtualisée d'UE5, qui affiche des millions de triangles efficacement.
Niagara
Le système d'effets visuels et de particules.

O – R

Outliner
Le panneau qui liste les Actors du niveau. Voir Prendre en main l'éditeur.
Packaging
La production d'un exécutable distribuable du jeu.
Pawn
Un Actor qui peut être possédé par un Controller ; le Character en est la version bipède.
PIE (Play In Editor)
Lancer le jeu dans l'éditeur, sur une copie du monde.
PlayerController
La représentation du joueur humain : il reçoit les entrées et possède un Pawn.
Possession
Le lien entre un Controller (cerveau) et un Pawn (corps).
Post Process
Les effets appliqués à l'image finale : exposition, bloom, étalonnage, flou.
Quaternion (FQuat)
Une représentation des rotations sans blocage de cardan, idéale pour interpoler.
Redirector
Le fichier laissé à l'ancien emplacement d'un asset déplacé ; à nettoyer avec Fix Up Redirectors.
Reflection (réflexion)
Le système qui rend les classes C++ visibles par l'éditeur, les Blueprints, le GC et le réseau (UCLASS, UPROPERTY…).
RepNotify
Une fonction appelée sur les clients quand une variable répliquée change.
Replication (réplication)
La synchronisation d'Actors et de variables du serveur vers les clients.
Root Motion
Un déplacement piloté par l'animation elle-même plutôt que par le code.
RPC (Remote Procedure Call)
Une fonction appelée sur une autre machine : Server, Client ou NetMulticast.

S – Z

SaveGame
Un objet dont les variables sont écrites sur le disque pour sauvegarder la progression.
Shipping
La configuration de build finale, optimisée et sans outils de débogage.
Skeletal Mesh / Static Mesh
Un mesh animé par un squelette, et un mesh rigide.
Socket
Un point d'attache nommé sur un mesh (main, bouche du canon).
Spring Arm
Le composant « perche » qui place la caméra derrière le personnage et gère les obstacles.
State Machine
Un ensemble d'états reliés par des transitions, utilisé en animation et pour l'IA (StateTree).
Subsystem
Un objet singleton géré par le moteur, attaché au jeu, au monde ou au joueur.
Tick
La mise à jour d'un objet à chaque frame.
Timeline
Un nœud Blueprint qui fait varier des valeurs selon des courbes, sur une durée.
Timer
Un appel de fonction programmé après un délai, éventuellement en boucle.
Trace (line trace, sweep)
Un rayon ou une forme lancés dans le monde pour détecter ce qu'ils touchent.
Transform
Position, rotation et échelle d'un objet.
UObject
La classe de base de presque tous les objets du moteur, gérée par le GC.
UHT (Unreal Header Tool)
L'outil qui lit les macros des en-têtes et génère le code de réflexion.
UMG (Unreal Motion Graphics)
Le système d'interface utilisateur à base de widgets.
Viewport
La vue 3D de l'éditeur, ou la zone d'affichage du jeu.
World Partition
Le découpage automatique d'un grand monde en cellules chargées selon la position du joueur.

Et après ?

  1. Terminez Orb Rush, puis modifiez-leAjoutez une mécanique (un dash, un deuxième type d'ennemi, un niveau) : c'est en sortant du tutoriel qu'on apprend vraiment.
  2. Faites une game jamUn thème, une contrainte de temps, un jeu fini. Rien ne fait progresser plus vite.
  3. Choisissez une spécialitéGameplay, IA, réseau, outils, rendu, animation technique : approfondissez avec la documentation et le code source.
  4. Lisez du codeCelui des projets d'exemple et du moteur. Vous y trouverez des solutions élégantes à des problèmes que vous n'aviez pas encore.
  5. Montrez votre travailPubliez vos jeux sur itch.io, partagez vos progrès : les retours des joueurs valent tous les tutoriels.

La documentation en ligne d'une fonction C++ du moteur est très succincte et ne précise pas un cas particulier. Quelle est la source la plus fiable pour lever le doute ?

  • Une vidéo YouTube de 2019
  • Le code source et les commentaires de l'en-tête de la fonction, pour votre version du moteur
  • Une réponse de forum sans version précisée
  • Essayer des valeurs au hasard jusqu'à ce que ça marche

Le code source correspond exactement à votre version et ne peut pas être « en retard ». Les vidéos et forums restent utiles, mais vérifiez toujours la version du moteur concernée.

Disséquer un projet d'exemple

Ouvrez le template Third Person (ou Stack O Bot) et répondez sans aide extérieure : quelle classe de GameMode est utilisée ? Quel Mapping Context est ajouté, et à quel endroit ? Quelle est la vitesse de marche maximale du personnage ? Quelle animation est jouée quand il saute ?

Voir la méthode
  1. GameMode : World Settings → GameMode Override, ou à défaut Project Settings → Maps & Modes → Default GameMode. Ouvrez-le : ses Class Defaults indiquent la classe de Pawn par défaut.
  2. Mapping Context : ouvrez le Blueprint du personnage et cherchez (Ctrl + F dans le graphe) « Add Mapping Context ». Selon la version du template, il est ajouté dans le personnage ou dans le PlayerController.
  3. Vitesse : sélectionnez le Character Movement Component du personnage, puis cherchez « Max Walk Speed » dans Details.
  4. Animation de saut : dans le composant Mesh, la propriété Anim Class indique l'Animation Blueprint ; ouvrez sa State Machine et suivez l'état de saut ou de chute. Le Reference Viewer sur l'Animation Blueprint liste aussi toutes les animations utilisées.

Cette démarche (partir de ce qu'on voit, remonter les références) fonctionne sur n'importe quel projet, y compris Lyra.

À retenir

  • La documentation officielle est la référence ; sélectionnez toujours votre version du moteur.
  • Le code source du moteur répond quand la documentation se tait : Aller à la définition et lisez les en-têtes.
  • Les projets d'exemple (Content Examples, Stack O Bot, Cropout, Lyra…) s'étudient un système à la fois.
  • Pour se débloquer : lire l'erreur, isoler, réduire à une reproduction minimale, puis poser une question précise (version, attendu, obtenu, essais).
  • Le glossaire et la checklist de cette page renvoient vers le chapitre qui explique chaque notion.
  • La meilleure ressource reste la pratique : finir de petits jeux, participer à des game jams, lire du code.
