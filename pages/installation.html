Installation & premier projet

Un environnement bien installé vous épargnera des heures de frustration. Dans ce chapitre, vous installez Unreal Engine 5 et un éditeur de code, vous créez votre premier projet C++, vous comprenez à quoi sert chacun de ses dossiers, puis vous le mettez sous gestion de versions. À la fin, vous aurez écrit et compilé votre première classe.

Dans ce chapitre

  • Installer UE5 avec l'Epic Games Launcher (ou depuis les sources GitHub) et choisir les bonnes options
  • Configurer Visual Studio 2022, Rider ou VS Code pour le C++ Unreal
  • Créer un projet à partir d'un template et comprendre l'arborescence d'un projet
  • Comprendre la chaîne de compilation : Unreal Build Tool, Unreal Header Tool, Live Coding
  • Écrire votre première classe C++ et votre premier Blueprint
  • Versionner votre projet avec Git LFS ou Perforce et résoudre les problèmes classiques

Avant de commencer

Unreal Engine est un logiciel lourd : l'éditeur compile des milliers de shaders (petits programmes exécutés par la carte graphique), manipule des textures de plusieurs centaines de mégaoctets et, si vous codez en C++, compile un projet de plusieurs millions de lignes. La machine compte donc davantage qu'avec un moteur plus léger.

Installer Unreal Engine

Compte Epic et Epic Games Launcher

La méthode standard passe par l'Epic Games Launcher, l'application qui sert aussi de boutique de jeux. Il vous faut un compte Epic Games gratuit. Unreal Engine est gratuit à télécharger ; une redevance ne s'applique qu'au-delà d'un certain chiffre d'affaires par jeu (les conditions exactes sont détaillées dans le chapitre Packaging & publication).

  1. Installer le LauncherTéléchargez-le depuis le site d'Unreal Engine, installez-le puis connectez-vous avec votre compte Epic.
  2. Ouvrir l'onglet Unreal EngineDans la colonne de gauche, cliquez sur Unreal Engine, puis sur l'onglet Library en haut. La section Engine Versions liste les moteurs installés.
  3. Ajouter une versionCliquez sur le bouton + à côté de Engine Versions. Une vignette apparaît : choisissez la version dans sa liste déroulante. Prenez la dernière version stable (5.x la plus récente), sauf si un cours ou une équipe vous impose une version précise.
  4. Choisir les optionsCliquez sur Install, choisissez un dossier sur un SSD, puis ouvrez Options pour sélectionner les composants (voir ci-dessous).
  5. PatienterLe téléchargement fait plusieurs dizaines de gigaoctets. Une fois terminé, le bouton Launch ouvre le Project Browser.

Les options d'installation

Le bouton Options de la vignette du moteur permet d'ajouter ou de retirer des composants, même après l'installation. Voici ce qu'ils contiennent :

Core Components
Le moteur et l'éditeur. Obligatoire.
Starter Content
Quelques meshes, matériaux et sons de démonstration. Pratique pour prototyper, inutile en production.
Templates and Feature Packs
Les modèles de projets (Third Person, First Person…) et les packs ajoutables à un projet existant. Gardez-les : vous en aurez besoin pour créer vos projets.
Engine Source
Le code source C++ du moteur, en lecture. Très utile pour comprendre ce que fait une fonction en y naviguant depuis votre IDE.
Editor symbols for debugging
Les fichiers de symboles (.pdb) du moteur. Très volumineux (souvent plus de 50 Go), mais indispensables pour suivre un plantage ou poser un point d'arrêt dans le code du moteur. Sans eux, la pile d'appels d'un crash est illisible.
Target Platforms
Les plateformes vers lesquelles vous pourrez empaqueter votre jeu : Android, iOS, Linux… Windows est toujours inclus sur un PC Windows. N'ajoutez que ce dont vous avez besoin.

Le bon compromis pour débuter

Cochez Starter Content, Templates and Feature Packs et Engine Source. Ajoutez les Editor symbols for debugging dès que vous commencez vraiment le C++ et que l'espace disque le permet : le premier crash dans le moteur vous fera regretter de ne pas les avoir.

Linux et macOS

C'est la plateforme de référence : toute la documentation, tous les outils et la plupart des tutoriels partent du principe que vous êtes sous Windows 10 ou 11 en 64 bits. Le Launcher installe tout, et Visual Studio fournit le compilateur.

Le Launcher existe sur macOS et UE5 fonctionne nativement sur les Mac à puce Apple Silicon. Vous devez installer Xcode depuis l'App Store : il fournit le compilateur Clang et les SDK Apple, indispensables pour compiler du C++ et pour cibler iOS. Certaines fonctionnalités de rendu dépendent du matériel et de la version : vérifiez les notes de version.

Il n'y a pas de Launcher officiel sous Linux. Deux solutions :

  • Les binaires précompilés : Epic publie une archive de l'éditeur sur unrealengine.com/linux (connexion à votre compte Epic requise). Décompressez-la, puis lancez Engine/Binaries/Linux/UnrealEditor. La chaîne de compilation Clang est fournie.
  • Compiler depuis les sources (section suivante) : plus long, mais vous choisissez exactement la version et vous pouvez modifier le moteur.

Comme éditeur de code, utilisez Rider ou VS Code. Les pilotes graphiques propriétaires (NVIDIA) ou Mesa récents (AMD) sont fortement recommandés, Vulkan étant l'API de rendu utilisée.

Compiler le moteur depuis les sources

Le code source complet d'Unreal Engine est disponible sur GitHub, dans un dépôt privé de l'organisation EpicGames. Il est gratuit, mais l'accès demande de lier vos comptes.

Quand en avez-vous besoin ?

  • Serveurs dédiés : la cible Server ne peut être compilée qu'avec un moteur construit depuis les sources.
  • Modifier le moteur : corriger un bug d'Epic sans attendre la prochaine version, ajouter une fonctionnalité au rendu, adapter un outil.
  • Utiliser une branche précise : une version de développement, ou une version patchée par votre studio.
  • Linux, si vous ne voulez pas des binaires précompilés.

Pour apprendre et pour la grande majorité des projets solo, la version du Launcher suffit amplement. Le moteur source coûte cher : plus de 150 Go d'espace et plusieurs heures de compilation initiale.

Les étapes

  1. Lier GitHub à votre compte EpicSur le site d'Epic Games, ouvrez les paramètres de votre compte, section Apps and Accounts (applications et comptes), et connectez votre compte GitHub.
  2. Accepter l'invitationVous recevez par e-mail une invitation à rejoindre l'organisation EpicGames sur GitHub. Tant que vous ne l'avez pas acceptée, l'adresse du dépôt github.com/EpicGames/UnrealEngine affiche une erreur 404.
  3. Cloner et préparerClonez la branche voulue (release pour la dernière version stable), puis lancez les scripts qui téléchargent les dépendances binaires et génèrent la solution.
  4. CompilerSous Windows, ouvrez UE5.sln, choisissez la configuration Development Editor et la plateforme Win64, puis compilez le projet UE5. Comptez une à plusieurs heures selon votre processeur.

Projet et moteur doivent être compatibles

Un projet ouvert avec un moteur source est lié à ce moteur (le champ EngineAssociation du fichier .uproject contient alors un identifiant unique au lieu d'un numéro de version). Toute votre équipe doit utiliser le même moteur compilé, sinon chacun recompile le projet de son côté et les assets peuvent devenir incompatibles.

Choisir et configurer un IDE

Un IDE (environnement de développement intégré) regroupe un éditeur de texte, un compilateur, un débogueur et des outils de navigation. Pour le C++ Unreal, trois options dominent.

Windows

Visual Studio 2022

L'IDE historique de Microsoft, gratuit en édition Community pour les particuliers et les petites structures. Il fournit aussi le compilateur MSVC dont le moteur a besoin sous Windows.

Windows, macOS, Linux

JetBrains Rider

Excellent support d'Unreal : il comprend les macros UPROPERTY, les Blueprints dérivés, les fichiers .ini. Gratuit pour un usage non commercial depuis fin 2024.

macOS, Linux

VS Code et Xcode

VS Code est léger et suffit avec les extensions C++. Sur macOS, Xcode est de toute façon nécessaire pour le compilateur, même si vous codez dans un autre éditeur.

Installer Visual Studio 2022

Dans le Visual Studio Installer, cochez les charges de travail (workloads) suivantes :

  • Développement Desktop en C++ (Desktop development with C++) : le compilateur MSVC et les outils de build ;
  • Développement de jeux en C++ (Game development with C++), puis dans le panneau de droite le composant Programme d'installation d'Unreal Engine et l'intégration Unreal Engine (IDE support for Unreal Engine) qui ajoute la coloration des macros, l'affichage des Blueprints qui utilisent une classe et des tests ;
  • un Windows SDK récent (Windows 10 ou 11), normalement coché par défaut ;
  • selon votre version du moteur, le composant .NET demandé par Unreal Build Tool (le moteur embarque souvent son propre runtime .NET, mais les notes de version le précisent).

Quelle version du compilateur ?

Chaque version d'Unreal est testée avec une version précise du compilateur MSVC et du Windows SDK, indiquée dans ses notes de version (Release Notes, section Platform SDK Upgrades). Les versions récentes du moteur peuvent aussi supporter des éditions plus récentes de Visual Studio : vérifiez avant d'installer. Si une compilation échoue avec une erreur bizarre juste après une mise à jour de Visual Studio, c'est souvent la piste à suivre.

Indiquer l'IDE à Unreal

L'éditeur doit savoir quel programme ouvrir quand vous double-cliquez sur une classe C++. Dans Edit → Editor Preferences → General → Source Code, réglez Source Code Editor sur Visual Studio 2022, Rider, VS Code ou Xcode. Le menu Tools propose ensuite Open Visual Studio (ou l'équivalent) et Refresh … Project pour régénérer les fichiers de projet ; le libellé exact dépend de l'éditeur choisi.

Rider : ouvrez directement le .uproject

Rider sait ouvrir un fichier .uproject sans passer par la solution Visual Studio. Au premier lancement, acceptez l'installation du plugin RiderLink dans le projet ou dans le moteur : il permet à Rider de dialoguer avec l'éditeur (journaux, Blueprints dérivés, lancement du jeu).

Créer votre premier projet

Au lancement, l'éditeur affiche le Project Browser. À gauche, des catégories regroupent les modèles de projets (templates) par secteur d'activité : Games, Film / Video & Live Events, Architecture, Automotive et Simulation (les intitulés exacts varient légèrement selon les versions). Pour faire un jeu, restez dans Games.

Les options du projet

Blueprint / C++
En C++, le projet contient un dossier Source et un module compilé. Vous pourrez toujours utiliser des Blueprints. En Blueprint, vous pourrez ajouter du C++ plus tard (Tools → New C++ Class convertit le projet), mais autant partir en C++ si vous comptez coder.
Target Platform
Desktop (PC, consoles) ou Mobile. Cela règle des paramètres de rendu par défaut ; ce n'est pas définitif.
Quality Preset
Maximum active les fonctionnalités de rendu haut de gamme (Lumen, etc.) ; Scalable désactive les plus coûteuses pour viser du matériel modeste.
Starter Content
Copie le contenu de démonstration dans le projet. Pratique pour un prototype, mais il alourdit le projet.
Raytracing
Active le ray tracing matériel si votre carte le supporte. Laissez décoché pour débuter.

Bien nommer son projet

Le nom du projet devient le nom du module C++ et de nombreuses classes. Il doit commencer par une lettre, sans espaces, sans accents ni caractères spéciaux, et rester court (une vingtaine de caractères au plus) : OrbRush, MyGame. Placez aussi le projet dans un chemin court (C:\Dev\OrbRush) : sous Windows, les chemins de plus de 260 caractères provoquent des erreurs de compilation et de packaging difficiles à comprendre.

Notre recommandation : template Third Person, projet C++, Desktop, Maximum, avec Starter Content. Le template fournit un personnage jouable et l'Enhanced Input déjà configuré, et la version C++ vous montre comment ce personnage est codé.

L'anatomie d'un projet

Un projet Unreal est un dossier dont la racine contient un fichier .uproject. Certains dossiers sont la source de vérité (à sauvegarder précieusement), d'autres sont générés et peuvent être supprimés sans risque.

  • MyGame/Racine du projet
    • MyGame.uprojectDescription du projet (JSON) : version du moteur, modules, plugins
    • MyGame.slnSolution Visual Studio, générée
    • Config/Réglages du projet, versionnés
      • DefaultEngine.iniRendu, physique, carte de démarrage, collisions
      • DefaultGame.iniInformations du jeu, packaging
      • DefaultInput.iniRéglages d'entrées (les actions Enhanced Input sont, elles, des assets)
      • DefaultEditor.iniRéglages de l'éditeur partagés par l'équipe
    • Content/Tous les assets : .uasset (meshes, Blueprints, textures…) et .umap (niveaux)
    • Source/Le code C++
      • MyGame.Target.csCible « jeu » (le jeu empaqueté)
      • MyGameEditor.Target.csCible « éditeur » (ce que vous compilez au quotidien)
      • MyGame/Le module principal
        • MyGame.Build.csDépendances du module (Core, Engine, EnhancedInput…)
        • MyGame.h / MyGame.cppDéclaration du module
        • MyGameCharacter.h / .cppVos classes (éventuellement rangées dans Public/ et Private/)
    • Plugins/Plugins propres au projet (optionnel)
    • Binaries/DLL et exécutables compilés, générés
    • Intermediate/Fichiers temporaires de compilation et code généré par UHT
    • Saved/Logs/, Autosaves/, Config/ (réglages locaux), Crashes/
    • DerivedDataCache/Cache des données dérivées (shaders compilés, textures compressées). Selon la version et la configuration, ce cache peut aussi vivre dans un dossier partagé de votre profil utilisateur

En rouge, les éléments générés : Binaries, Intermediate, Saved, DerivedDataCache et le fichier .sln (ainsi que les dossiers cachés .vs ou .idea des IDE). Les supprimer règle beaucoup de problèmes de compilation « inexplicables ». Pour régénérer la solution, faites un clic droit sur le fichier .uproject → Generate Visual Studio project files (sous Windows, ce menu est installé avec le moteur), ou utilisez Tools → Refresh … Project dans l'éditeur.

Attention avant de supprimer Saved/

Saved/ contient aussi les sauvegardes automatiques (Autosaves) et, en développement, les fichiers SaveGame de votre jeu. Si vous venez de perdre un niveau suite à un crash, regardez dans Saved/Autosaves avant de faire le ménage.

Le fichier .uproject

C'est un simple fichier JSON. Double-cliquer dessus ouvre le projet dans l'éditeur. Clic droit → Switch Unreal Engine version permet de l'associer à un autre moteur installé.

Les fichiers .Build.cs et .Target.cs

Ces fichiers sont écrits en C# : ils sont lus par Unreal Build Tool, lui-même écrit en C#. Le .Build.cs décrit un module (une bibliothèque de code compilée séparément) et surtout ses dépendances : si vous utilisez une classe d'un autre module (l'UI, l'IA, Niagara…), il faut ajouter ce module ici, sinon l'édition de liens échoue avec une erreur unresolved external symbol.

Comment le C++ est compilé

Le C++ standard ne sait pas qu'une variable doit apparaître dans l'éditeur ou être accessible en Blueprint. Unreal ajoute donc une étape avant le compilateur : la génération de code.

Unreal Build Tool
UBT, le chef d'orchestre. Il lit les fichiers .Target.cs et .Build.cs, détermine quels modules compiler, appelle UHT, puis le compilateur et l'éditeur de liens avec les bons paramètres.
Unreal Header Tool
UHT parcourt vos fichiers .h à la recherche des macros UCLASS, UPROPERTY, UFUNCTION… et génère le code qui décrit vos classes au moteur (le système de réflexion). C'est pourquoi chaque header se termine par #include "MyActor.generated.h", qui doit rester le dernier include.
Module
Une unité de code compilée en une bibliothèque (une DLL dans l'éditeur). Votre jeu est un module ; le moteur en compte des centaines.

Live Coding

Live Coding recompile votre code pendant que l'éditeur est ouvert et remplace à chaud les fonctions modifiées. Raccourci : Ctrl + Alt + F11 dans l'éditeur, ou le bouton de compilation en bas à droite de la fenêtre. C'est idéal pour ajuster le corps d'une fonction et voir le résultat en quelques secondes.

Mais Live Coding a des limites : il gère mal les changements de structure d'une classe. Dans ces cas, fermez l'éditeur, compilez depuis l'IDE, puis relancez :

Live Coding suffit

  • Modifier le corps d'une fonction dans un .cpp
  • Changer une valeur, une formule, un message de log
  • Ajouter une fonction non exposée (sans UFUNCTION) dans un .cpp

Fermez l'éditeur et compilez

  • Ajouter ou modifier une UPROPERTY ou une UFUNCTION
  • Créer une nouvelle classe, ajouter des variables membres
  • Changer les valeurs par défaut dans un constructeur
  • Modifier un .Build.cs ou les modules du .uproject

Compiler depuis l'IDE

Dans Visual Studio, choisissez la configuration Development Editor et la plateforme Win64 dans la barre d'outils, vérifiez que votre projet de jeu (et non UE5) est le projet de démarrage, puis appuyez sur F5 : le projet est compilé et l'éditeur s'ouvre avec le débogueur attaché. Vos points d'arrêt fonctionnent alors directement.

ConfigurationUsage
Development EditorLe quotidien : éditeur avec votre code optimisé mais débogable
DebugGame EditorVotre code sans optimisations (variables toutes visibles dans le débogueur), moteur optimisé

« Unable to build while Live Coding is active »

Vous ne pouvez pas compiler depuis l'IDE tant que l'éditeur est ouvert avec Live Coding activé. Fermez l'éditeur, ou compilez avec Ctrl + Alt + F11 depuis l'éditeur lui-même.

Votre première classe C++

Dans l'éditeur, ouvrez Tools → New C++ Class. Choisissez la classe parente Actor, cliquez sur Next, nommez la classe MyActor puis Create Class. L'éditeur génère deux fichiers dans Source/MyGame/ et compile le module. Si la classe n'apparaît pas dans le Content Browser (dossier C++ Classes), fermez l'éditeur et compilez depuis l'IDE.

UCLASS()
Déclare la classe au système de réflexion : elle devient visible dans l'éditeur et peut servir de parent à un Blueprint.
MYGAME_API
Macro d'export du module (nom du module en majuscules suivi de _API) : elle rend la classe utilisable depuis d'autres modules.
GENERATED_BODY()
Insère le code généré par UHT. Obligatoire, en première ligne de la classe.
Super::BeginPlay()
Appelle la version de la classe parente. L'oublier casse des comportements du moteur (composants non initialisés, Blueprints dont le BeginPlay ne se déclenche pas).

Toutes ces notions sont détaillées dans le chapitre C++ pour Unreal : les bases.

Hello World, en Blueprint et en C++

Affichons un message au démarrage du jeu. En Blueprint, ouvrez un Blueprint d'Actor (ou le Level Blueprint via le bouton Blueprints de la barre d'outils) ; en C++, complétez le BeginPlay de AMyActor, puis glissez l'Actor dans le niveau et lancez Play.

Où voir les messages ?

Ouvrez Window → Output Log. Les messages UE_LOG y apparaissent avec leur catégorie (LogTemp) ; ils sont aussi écrits dans Saved/Logs/MyGame.log. Les messages à l'écran disparaissent du jeu empaqueté en configuration Shipping : ils servent au débogage, pas à l'interface du joueur.

Vous venez d'ajouter une nouvelle UPROPERTY dans le header d'une classe. Quelle est la méthode la plus fiable pour la voir dans l'éditeur ?

  • Appuyer sur Ctrl + S dans l'éditeur
  • Lancer Live Coding et espérer que ça passe
  • Fermer l'éditeur, compiler depuis l'IDE en Development Editor, puis relancer
  • Supprimer le dossier Content

Une nouvelle UPROPERTY change la structure de la classe et le code généré par Unreal Header Tool. Live Coding est fait pour les modifications de corps de fonctions ; pour les headers, la recompilation complète éditeur fermé est la voie sûre. Et ne supprimez jamais Content : ce sont vos assets !

Versionner son projet

Un système de gestion de versions (version control, ou revision control) enregistre l'historique de chaque fichier. Même seul, c'est indispensable :

  • Sauvegarde : un disque qui lâche ou un niveau corrompu ne vous coûte plus des semaines de travail ;
  • Historique : vous pouvez revenir à la version d'hier quand une modification casse tout ;
  • Travail en équipe : plusieurs personnes modifient le projet sans s'écraser mutuellement.

Le problème des fichiers binaires

Le code est du texte : si deux personnes modifient le même .cpp, l'outil sait fusionner (merge) leurs changements ligne par ligne. Mais les .uasset et .umap sont des fichiers binaires : impossible de les fusionner. Si deux personnes modifient le même Blueprint en parallèle, l'une des deux perdra son travail. La solution est le verrouillage (file locking) : avant de modifier un asset, on le verrouille, et personne d'autre ne peut le modifier tant qu'il n'est pas libéré.

Git et Git LFS

Git est le standard du développement logiciel, mais il gère mal les gros fichiers binaires. Git LFS (Large File Storage) le complète : les gros fichiers sont stockés à part et Git ne garde qu'un petit pointeur. LFS apporte aussi le verrouillage. Les hébergeurs (GitHub, GitLab, Azure DevOps…) le supportent, avec des quotas de stockage LFS à surveiller.

Créez le .gitattributes avant le premier commit

Si vous commitez des .uasset avant d'avoir configuré LFS, ils entrent dans l'historique Git « normal » et y restent pour toujours, gonflant le dépôt. Les corriger après coup demande de réécrire l'historique (git lfs migrate), ce qui est délicat en équipe.

Perforce et les autres options

Perforce (Helix Core, renommé P4) est le standard de l'industrie du jeu vidéo, et l'outil qu'Epic utilise en interne. Il est conçu pour les dépôts de plusieurs téraoctets et le verrouillage y est natif (exclusive checkout : un asset ouvert en modification est bloqué pour les autres). Il est gratuit pour les petites équipes, dans la limite de quelques utilisateurs (vérifiez les conditions actuelles). Son inconvénient : il faut héberger et administrer un serveur.

Autres solutions rencontrées : Unity Version Control (ex-Plastic SCM), Subversion, ou des outils récents pensés pour les artistes comme Anchorpoint ou Diversion.

La gestion de versions dans l'éditeur

L'éditeur intègre un module Revision Control (appelé Source Control dans les versions plus anciennes), accessible en bas à droite de la fenêtre. Une fois connecté à Perforce, Git ou Subversion, il affiche l'état de chaque asset dans le Content Browser (verrouillé par vous, par un collègue, modifié…) et propose de verrouiller automatiquement un asset quand vous le modifiez. Le plugin Git fourni par Epic est basique ; beaucoup d'équipes Git utilisent le plugin communautaire de Project Borealis, qui gère les verrous LFS.

Lisez la première erreur, pas la dernière

Une seule faute de frappe dans un header peut générer des dizaines d'erreurs en cascade. Dans Visual Studio, ouvrez la fenêtre Output (plus fiable que la liste Error List, qui mélange IntelliSense et vraies erreurs) et remontez à la toute première erreur du compilateur.

Documentation officielle

Dans la documentation d'Epic, cherchez « Installing Unreal Engine », « Setting Up Visual Studio for Unreal Engine », « Downloading Source Code » et « Live Coding ». Les Release Notes de chaque version listent les versions de compilateurs et de SDK supportées.

Quels dossiers d'un projet Unreal peut-on supprimer sans perdre de travail (le moteur les régénère) ?

  • Content et Config
  • Source et Plugins
  • Binaries, Intermediate et DerivedDataCache
  • Le fichier .uproject et le dossier Content

Binaries (code compilé), Intermediate (fichiers temporaires et code généré) et DerivedDataCache (cache) sont reconstruits à la prochaine compilation et au prochain lancement. Content, Config, Source, Plugins et le .uproject sont vos sources : ce sont eux qu'il faut versionner. Pour Saved, pensez d'abord aux sauvegardes automatiques qu'il contient.

Votre premier projet versionné

Créez un projet Third Person en C++ nommé FirstSteps. Ajoutez une classe C++ AGreeterActor (parent Actor) qui affiche à l'écran et dans l'Output Log « Bienvenue dans FirstSteps » au démarrage, sans utiliser Tick. Placez-la dans le niveau et vérifiez le message en jouant. Enfin, versionnez le projet avec Git et Git LFS.

Voir la solution
  1. Project Browser → Games → Third Person → C++ → nom FirstSteps → Create.
  2. Tools → New C++ Class → Actor → nom GreeterActor. Fermez l'éditeur, remplacez le code par celui ci-dessous, compilez en Development Editor / Win64 et relancez avec F5.
  3. Dans le Content Browser, dossier C++ Classes → FirstSteps, glissez GreeterActor dans le niveau, puis Play.
  4. À la racine du projet, créez le .gitignore et le .gitattributes de ce chapitre avant le premier commit, puis lancez git init, git lfs install, git add . et git commit. Vérifiez avec git lfs ls-files que les .uasset sont bien gérés par LFS.

Notez la macro FIRSTSTEPS_API : elle reprend le nom du module, ici FirstSteps.

À retenir

  • Installez UE5 via l'Epic Games Launcher ; ajoutez Engine Source et, pour déboguer, les Editor symbols. Le moteur source (GitHub) n'est utile que pour les serveurs dédiés ou les modifications du moteur.
  • Sous Windows, Visual Studio 2022 avec les workloads C++ Desktop et Jeux ; Rider est une excellente alternative sur toutes les plateformes.
  • Partez d'un template Third Person en C++, avec un nom court sans espaces dans un chemin court.
  • Content, Config, Source et le .uproject sont vos sources ; Binaries, Intermediate, Saved et DerivedDataCache sont générés.
  • UBT orchestre la compilation, UHT génère le code de réflexion. Live Coding pour les .cpp, éditeur fermé pour les changements de headers.
  • Versionnez dès le premier jour : Git + LFS (avec verrous) ou Perforce, car les assets binaires ne se fusionnent pas.
