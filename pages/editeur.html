Prendre en main l'éditeur

L'éditeur d'Unreal Engine impressionne la première fois : des dizaines de panneaux, de menus et de boutons. Bonne nouvelle, vous n'utiliserez au quotidien qu'une poignée d'entre eux. Ce chapitre vous fait visiter l'interface, vous apprend à vous déplacer dans la scène comme un level designer, à retrouver vos assets et à les nommer proprement, puis à tester votre jeu sans quitter l'éditeur.

Dans ce chapitre

  • Reconnaître les panneaux principaux de l'éditeur et leur rôle
  • Naviguer dans le Viewport à la souris, au clavier et avec le gizmo
  • Organiser la scène avec l'Outliner et régler les objets dans le panneau Details
  • Gérer vos assets dans le Content Browser : import, dossiers, redirecteurs
  • Appliquer des conventions de nommage et une arborescence de dossiers propres
  • Tester le jeu avec Play In Editor et Simulate

Vue d'ensemble de l'interface

Quand vous ouvrez un projet, l'éditeur affiche le Level Editor : l'outil qui sert à construire des niveaux. Chaque type d'asset (Blueprint, matériau, animation…) possède ensuite son propre éditeur, qui s'ouvre dans un nouvel onglet quand vous double-cliquez dessus. Voici la disposition par défaut d'UE5 :

Le Content Drawer

Pour garder un maximum de place au viewport, UE5 range le Content Browser dans un tiroir (Content Drawer) qui s'ouvre avec Ctrl + Espace et se referme dès que vous cliquez ailleurs. Le bouton Dock in Layout l'ancre en permanence si vous préférez.

Les modes d'édition

Le menu déroulant Modes de la barre d'outils (ou Maj + 1 à 8) change ce que fait le viewport : sélectionner des Actors (Selection, le mode par défaut), sculpter un terrain (Landscape), peindre de la végétation (Foliage), modéliser (Modeling), peindre des couleurs de sommets (Mesh Paint)… Si le viewport ne réagit plus comme d'habitude, vérifiez d'abord que vous êtes bien en mode Selection.

Naviguer dans le Viewport

Se déplacer vite dans la scène est la première compétence à acquérir. La méthode la plus efficace, utilisée par tous les level designers, est le vol libre façon jeu vidéo : maintenez le clic droit et utilisez ZQSD (ou WASD en QWERTY).

L'éditeur détecte la disposition de votre clavier pour la plupart des raccourcis de déplacement, mais certains tutoriels citent les touches QWERTY. En cas de doute, les raccourcis réels sont listés (et modifiables) dans Edit → Editor Preferences → Keyboard Shortcuts.

Le repère et les unités

Unreal utilise un repère où X pointe vers l'avant (rouge), Y vers la droite (vert) et Z vers le haut (bleu). Une unité vaut 1 centimètre : un personnage standard mesure environ 180 unités. Ces conventions sont détaillées dans le chapitre Maths du jeu vidéo ; retenez pour l'instant les couleurs, car le gizmo les reprend.

Le gizmo : déplacer, tourner, mettre à l'échelle

Une fois un Actor sélectionné (clic gauche dans le viewport ou dans l'Outliner), un gizmo apparaît. Il a trois modes, que l'on alterne avec les touches situées sous les chiffres :

W · Translation

Déplacer

Trois flèches colorées. Tirez une flèche pour bouger sur un axe, un carré entre deux flèches pour bouger sur un plan.

E · Rotation

Tourner

Trois arcs. Chaque arc fait tourner l'objet autour d'un axe : rouge = Roll (X), vert = Pitch (Y), bleu = Yaw (Z).

R · Échelle

Mettre à l'échelle

Des cubes au bout des axes. Le cube central agrandit uniformément sur les trois axes.

En haut à droite du viewport, la barre d'outils permet de basculer entre repère monde et repère local (icône globe ou cube, Ctrl + `) et de régler le magnétisme (snapping) : pas de grille en translation (10 cm par défaut), angle en rotation (10°), pas en échelle. Le magnétisme est indispensable pour assembler des murs et des sols modulaires sans trous.

Un objet est sélectionné mais il est hors de vue, quelque part dans un grand niveau. Quel est le moyen le plus rapide de le voir ?

  • Voler jusqu'à lui avec clic droit + ZQSD
  • Appuyer sur F pour centrer la vue sur la sélection
  • Appuyer sur G
  • Passer en vue orthographique

F (Focus) téléporte la caméra devant la sélection. Combiné à un double-clic dans l'Outliner, c'est la façon standard de retrouver un objet.

L'Outliner : la liste du niveau

L'Outliner affiche tous les Actors présents dans le niveau ouvert, y compris ceux qu'on ne voit pas dans le viewport (lumières d'ambiance, volumes, gestionnaires invisibles). C'est la vue « base de données » de votre scène.

  • Rechercher : la barre de recherche filtre par nom ; cliquez sur l'icône de filtre pour n'afficher qu'un type (lumières, Blueprints…).
  • Organiser : créez des dossiers (clic droit → Move To → Create New Folder). Ils n'existent que dans l'éditeur et n'ont aucun coût en jeu.
  • Attacher : glissez un Actor sur un autre pour l'attacher. L'enfant suit alors le parent quand on le déplace.
  • Visibilité et verrouillage : l'icône œil masque un Actor dans l'éditeur ; l'icône cadenas (selon votre version) empêche de le sélectionner par erreur dans le viewport.
  • Type et état : la colonne Type indique la classe de l'Actor ; avec World Partition, des colonnes indiquent aussi s'il est chargé.

Actor du niveau ou asset ?

Supprimer BP_Orb dans l'Outliner retire une instance du niveau : l'asset existe toujours dans le Content Browser. Supprimer l'asset BP_Orb dans le Content Browser le supprime du projet, et toutes ses instances deviennent invalides. Ne confondez pas les deux.

Le panneau Details

Le panneau Details affiche les propriétés de ce qui est sélectionné. Pour un Actor, on y trouve en haut sa hiérarchie de composants, puis les catégories de propriétés : Transform, Static Mesh, Materials, Physics, Collision, Rendering…

  • Transform : position (Location), rotation et échelle, en valeurs exactes. Cliquez sur la flèche jaune « réinitialiser » à droite d'un champ pour revenir à la valeur par défaut.
  • Recherche : la barre de recherche du panneau trouve une propriété parmi des centaines (tapez « collision », « shadow », « gravity »).
  • Glisser sur un champ : cliquer-glisser horizontalement sur l'étiquette d'un nombre change sa valeur en continu.
  • Sélection multiple : avec plusieurs Actors sélectionnés, une modification s'applique à tous ; les valeurs différentes s'affichent « Multiple Values ».
  • Mobility : Static (ne bouge jamais, éclairage précalculable), Stationary (lumières seulement) ou Movable (peut bouger en jeu). Un objet qui doit bouger doit être Movable.

Vos propres variables dans Details

Les variables que vous déclarez dans vos Blueprints ou vos classes C++ apparaissent elles aussi dans Details, si vous les exposez. C'est ce qui permet à un level designer de régler chaque instance sans toucher au code. En Blueprint, il suffit de cocher l'œil Instance Editable de la variable ; en C++, on utilise UPROPERTY (détaillé dans C++ pour Unreal : les bases) :

Placez deux ASpinningOrb dans le niveau : chacun a sa propre catégorie Orb dans Details, et vous pouvez donner une vitesse différente à chaque instance. La valeur écrite dans le code (90.f) n'est que la valeur par défaut.

Valeur modifiée, valeur par défaut

Une propriété dont la valeur diffère de celle de la classe affiche une petite flèche jaune de réinitialisation. Si vous changez ensuite la valeur par défaut dans le Blueprint ou le C++, seules les instances non modifiées héritent de la nouvelle valeur : les instances retouchées à la main gardent la leur.

Le Content Browser

Le Content Browser montre le contenu du dossier Content/ de votre projet : c'est là que vivent tous vos assets. Chaque asset est un fichier .uasset sur le disque (les niveaux sont des .umap). On n'y touche jamais depuis l'explorateur de fichiers : déplacer, renommer ou supprimer se fait toujours depuis l'éditeur, qui met à jour les références.

Importer des fichiers

Glissez-déposez un fichier depuis votre explorateur dans le Content Browser, ou utilisez le bouton Import. Unreal convertit le fichier source en asset :

Le fichier source n'est pas copié dans le projet : seul l'asset converti l'est. Gardez vos sources (fichiers Blender, PSD) dans un dossier à part, versionné lui aussi. Le bouton Reimport d'un asset relit son fichier source après une modification.

Le contenu gratuit

Le bouton Add → Add Feature or Content Pack ajoute à votre projet le contenu de démarrage (Starter Content), le personnage à la troisième personne, etc. Fab (la boutique d'Epic) propose aussi de nombreux assets gratuits, qui s'ajoutent directement depuis le panneau Fab de l'éditeur.

Déplacer et renommer : les redirecteurs

Quand vous déplacez ou renommez un asset, d'autres assets peuvent pointer vers son ancien chemin. Plutôt que de modifier tous ces fichiers, Unreal laisse un petit fichier invisible à l'ancien emplacement : un redirecteur (Redirector), qui renvoie vers le nouveau chemin.

Les redirecteurs s'accumulent et finissent par poser problème (dossiers impossibles à supprimer, conflits en équipe). Après une réorganisation, faites un clic droit sur le dossier Content → Fix Up Redirectors. Par défaut, le Content Browser masque les redirecteurs ; le filtre Show Redirectors les affiche.

Reference Viewer
Clic droit sur un asset → Reference Viewer : graphe de ce qui utilise l'asset et de ce qu'il utilise. Indispensable avant de supprimer quoi que ce soit.
Size Map
Clic droit → Size Map : la taille mémoire de l'asset et de tout ce qu'il charge avec lui (voir Débogage & optimisation).
Migrate
Clic droit → Asset Actions → Migrate : copie un asset et toutes ses dépendances vers un autre projet. C'est la seule façon fiable de transférer du contenu entre projets.
Collections
Des listes d'assets transversales aux dossiers (« Tout ce qui sert au boss »), privées ou partagées.

Conventions de nommage

Un projet de jeu contient vite des milliers d'assets. Un préfixe indiquant le type permet de les reconnaître d'un coup d'œil, de les trouver par la recherche (« M_Orb » ne remonte que des matériaux) et de les trier. La convention la plus répandue, inspirée du guide de style d'Allar et des projets d'Epic, est Préfixe_NomDeBase_Variante_Suffixe :

  • Matériau_Doré (accents et caractères spéciaux)
  • Des noms différents pour la même chose selon les dossiers

Pas d'espaces, pas d'accents, pas de chemins trop longs

Les caractères spéciaux et les espaces posent des problèmes à certains outils (contrôle de version, ligne de commande, consoles). Sous Windows, un chemin complet de fichier trop long (environ 260 caractères) peut aussi faire échouer le packaging : gardez des noms courts et ne placez pas votre projet au fond d'une arborescence profonde.

Organiser les dossiers

Deux grandes philosophies existent. La plus recommandée est le rangement par fonctionnalité : tout ce qui concerne l'orbe (Blueprint, mesh, matériau, son, effet) vit dans le même dossier. On sait ainsi immédiatement ce qu'il faut migrer ou supprimer avec une fonctionnalité.

Simple au début, mais une fonctionnalité finit éparpillée dans six dossiers : difficile de savoir quoi déplacer ou supprimer.

  1. Un dossier racine au nom du projetTout votre contenu dans Content/OrbRush/. Le contenu importé (packs Fab, Starter Content) reste à côté, isolé : vous savez ce qui est à vous.
  2. Un dossier MapsLes niveaux sont faciles à retrouver, et c'est le dossier qu'on liste dans les réglages de packaging.
  3. Un dossier Developers pour les essaisActivez-le dans les filtres du Content Browser : chaque membre de l'équipe a son bac à sable, exclu du jeu final s'il n'est référencé nulle part.
  4. Pas de dossiers vides ni trop profondsTrois ou quatre niveaux suffisent. Un dossier ne contenant qu'un asset est souvent inutile.

Vous voulez transférer le personnage « Gardien » (Blueprint, mesh, animations, matériaux) vers un autre projet. Comment faire ?

  • Copier les fichiers .uasset depuis l'explorateur Windows
  • Exporter chaque asset en FBX puis le réimporter
  • Clic droit sur le Blueprint → Asset Actions → Migrate, puis choisir le dossier Content du projet cible
  • Renommer le dossier puis faire Fix Up Redirectors

Migrate rassemble l'asset et toutes ses dépendances en conservant leurs chemins relatifs, ce qui garde les références valides. Copier à la main oublie presque toujours une dépendance.

Tester le jeu : Play In Editor

Le bouton ▶ Play de la barre d'outils (Alt + P) lance le jeu directement dans le viewport : c'est le Play In Editor (PIE). Le moteur crée une copie temporaire du niveau, y fait apparaître le joueur selon le GameMode, et exécute vos Blueprints et votre C++. Échap arrête la partie et revient à l'édition.

Le menu à trois points à côté de ▶ propose plusieurs façons de lancer :

ModeEffetQuand l'utiliser
Selected ViewportJoue dans le viewport actuel (par défaut)Tests rapides au quotidien
New Editor Window (PIE)Ouvre une fenêtre séparéeTester une résolution, le multijoueur à plusieurs fenêtres
Standalone GameLance un processus de jeu séparéComportement plus proche du jeu final, menus, chargement de niveaux
Simulate (Alt + S)Fait tourner le monde sans joueurObserver la physique ou une IA en se déplaçant librement

Le même menu règle le nombre de joueurs et le mode réseau (Play As Listen Server, Play As Client) ; voir Réseau & multijoueur. L'option Current Camera Location fait apparaître le joueur là où se trouve la caméra plutôt qu'au PlayerStart : très pratique pour tester un endroit précis.

Les raccourcis pendant une partie

Maj + F1
Libère le curseur de la souris pour cliquer dans l'éditeur sans arrêter la partie.
F8 (Eject)
Détache la caméra du joueur : le jeu continue, vous volez librement et pouvez sélectionner des Actors pour inspecter leurs valeurs en direct dans Details. F8 à nouveau pour reprendre le contrôle.
² (ou `)
Ouvre la console pour taper des commandes (stat fps, slomo 0.2…).
Pause
Met le jeu en pause ; le bouton Frame Skip avance alors d'une frame à la fois.

Le plus simple des tests consiste à afficher un message au démarrage de la partie. Dans le Level Blueprint (barre d'outils → icône Blueprints → Open Level Blueprint) :

Les modifications faites en jeu sont perdues

Pendant le PIE, vous pouvez déplacer des objets et changer des valeurs dans Details, mais tout disparaît à l'arrêt : c'était une copie. Pour garder un réglage trouvé en jeu, sélectionnez l'Actor et appuyez sur K (Keep Simulation Changes) avant d'arrêter, ou notez la valeur. À l'inverse, pensez à arrêter le PIE avant de modifier votre niveau.

Les réglages essentiels

Deux fenêtres de réglages reviennent sans cesse, et il est facile de les confondre :

Project Settings

Edit → Project Settings. Réglages du jeu, enregistrés dans Config/Default*.ini et partagés par toute l'équipe : cartes par défaut, GameMode par défaut, entrées, collisions, rendu, packaging.

Editor Preferences

Edit → Editor Preferences. Réglages de votre éditeur, personnels : raccourcis, langue, vitesse de la caméra, sauvegarde automatique, comportement du Live Coding.

Dans Project Settings, la page Maps & Modes définit le niveau ouvert au lancement de l'éditeur et du jeu, ainsi que le GameMode par défaut. Ces réglages sont écrits dans un fichier texte que vous pouvez lire et versionner :

Le suffixe _C désigne la classe générée par un Blueprint, par opposition à l'asset Blueprint lui-même : vous le reverrez dans les chemins de classes. Côté World Settings, le champ GameMode Override permet à un niveau précis (un menu, par exemple) d'utiliser un autre GameMode que celui par défaut.

Sauvegarder souvent, et tout

Ctrl + S enregistre le niveau courant ; Ctrl + Maj + S (Save All) enregistre tous les assets modifiés, signalés par un astérisque dans leur onglet ou leur vignette. Un asset modifié mais non sauvegardé n'existe pas pour le contrôle de version ni pour le packaging.

Pendant le PIE, vous réglez la hauteur d'une plateforme et trouvez enfin la bonne valeur. Vous appuyez sur Échap : la plateforme est revenue à sa hauteur d'origine. Pourquoi ?

  • Le niveau n'avait pas été sauvegardé avant de lancer le PIE
  • La plateforme était en Mobility Static
  • Le PIE travaille sur une copie du monde ; il fallait appuyer sur K (Keep Simulation Changes) avant d'arrêter
  • Il faut toujours utiliser Simulate pour modifier un niveau

Toutes les modifications faites pendant une partie dans l'éditeur sont appliquées à un monde temporaire, détruit à l'arrêt. Keep Simulation Changes recopie les propriétés de l'Actor sélectionné vers le niveau d'édition.

Votre première arène

Créez un nouveau niveau Lvl_Arena (File → New Level → Basic). Construisez une arène de 40 × 40 mètres avec un sol et quatre murs en utilisant le magnétisme, rangez les Actors dans des dossiers d'Outliner Geometry, Lighting et Gameplay, placez un PlayerStart au centre, et faites de ce niveau la carte de démarrage de l'éditeur. Lancez le PIE pour vérifier.

Voir la solution
  1. Rangez le niveau dans Content/OrbRush/Maps/ lors de la première sauvegarde (Ctrl + S).
  2. Ajoutez un Cube (bouton + → Shapes). Le cube de base mesure 100 cm : pour le sol, mettez son échelle à (40, 40, 0.2), ce qui donne 40 × 40 m sur 20 cm d'épaisseur, et sa position à (0, 0, -10).
  3. Pour un mur, échelle (40, 0.5, 4) et position (0, 2000, 200). Dupliquez-le avec Alt + glisser en gardant le magnétisme actif, puis tapez les positions exactes dans Details : (0, -2000, 200), et pour les deux autres une rotation Yaw de 90° et les positions (2000, 0, 200) et (-2000, 0, 200).
  4. Dans l'Outliner, sélectionnez sol et murs, clic droit → Move To → Create New Folder → Geometry. Faites de même pour la lumière, le ciel et le brouillard (Lighting).
  5. Ajoutez un PlayerStart (bouton + → Basic) en (0, 0, 100), rangez-le dans Gameplay.
  6. Project Settings → Maps & Modes → Editor Startup Map : choisissez Lvl_Arena. Lancez le PIE avec Alt + P.

Si le joueur tombe dans le vide, le sol n'a probablement pas de collision ou le PlayerStart est en dessous : l'icône du PlayerStart affiche « BAD size » quand il est mal placé.

À retenir

  • Le Level Editor réunit le Viewport, l'Outliner (les Actors du niveau), le panneau Details (leurs propriétés) et le Content Browser (les assets du projet).
  • Navigation : clic droit + ZQSD pour voler, F pour centrer, W/E/R pour le gizmo, magnétisme pour aligner.
  • Une instance dans l'Outliner n'est pas l'asset du Content Browser ; on déplace et renomme les assets uniquement dans l'éditeur, puis on fait Fix Up Redirectors.
  • Préfixes (BP_, M_, MI_, T_, SM_, WBP_…) et rangement par fonctionnalité sous un dossier racine au nom du jeu.
  • Les variables exposées (Instance Editable, UPROPERTY(EditAnywhere)) se règlent par instance dans Details.
  • Le PIE joue sur une copie du monde : Maj + F1 libère la souris, F8 éjecte la caméra, K conserve un réglage.
  • Project Settings = le jeu (partagé, fichiers .ini) ; Editor Preferences = votre confort personnel.
