Intelligence artificielle

Un garde qui patrouille, un monstre qui vous traque, un compagnon qui vous suit : Unreal fournit une boîte à outils complète pour l'IA de vos personnages. Ce chapitre vous apprend à assembler ses pièces (contrôleur, navigation, Behavior Trees, perception, EQS) pour construire un ennemi crédible, puis à le déboguer.

Dans ce chapitre

  • Comprendre le rôle de l'AIController et comment il possède un Pawn
  • Générer et régler le NavMesh pour que l'IA trouve son chemin
  • Concevoir un Behavior Tree avec son Blackboard, et maîtriser les observer aborts
  • Écrire des tâches et services en C++ et en Blueprint
  • Donner des sens à l'IA avec l'AI Perception (vue, ouïe)
  • Découvrir l'EQS et StateTree, et déboguer avec les outils du moteur

Vue d'ensemble

L'IA d'Unreal reprend l'idée centrale du Gameplay Framework (voir Architecture du moteur) : on sépare le cerveau du corps. Le corps est un Pawn ou un Character, exactement le même type de classe que le personnage du joueur. Le cerveau est un AAIController, qui possède ce Pawn comme un PlayerController le ferait, mais prend ses décisions seul.

Ce chapitre se concentre sur ce trio classique, utilisé dans la grande majorité des jeux Unreal. Epic propose aussi des alternatives plus récentes, que vous croiserez dans les projets d'exemple :

Plugin

StateTree

Une machine à états hiérarchique, alternative aux Behavior Trees, de plus en plus mise en avant par Epic. Présentée en fin de chapitre.

Plugin

Smart Objects

Des objets du décor qui « annoncent » une activité (s'asseoir sur ce banc, utiliser ce comptoir). L'IA réserve un emplacement libre puis joue le comportement associé.

Plugin

Mass

Un framework orienté données (ECS) pour simuler des milliers d'entités : foules, trafic. Chaque agent est bien plus léger qu'un Actor avec son AIController.

Modules à ajouter pour le C++

Dans le .Build.cs, ajoutez "AIModule" (contrôleur, Behavior Trees, perception), "NavigationSystem" (requêtes de navigation) et "GameplayTasks" (les tâches de Behavior Tree en dépendent) à PublicDependencyModuleNames.

L'AIController

Chaque Pawn possède deux réglages (section Pawn de ses Class Defaults) qui décident s'il sera contrôlé par une IA :

AI Controller Class
La classe de contrôleur à créer (AIControllerClass en C++). Par défaut, AAIController ; vous mettrez la vôtre, par exemple BP_EnemyController.
Auto Possess AI
Quand créer ce contrôleur automatiquement (AutoPossessAI) : Disabled, PlacedInWorld (seulement pour les Pawns posés dans le niveau, valeur par défaut), Spawned (seulement pour ceux créés en cours de jeu) ou PlacedInWorldOrSpawned.

Piège courant : l'ennemi spawné qui ne bouge pas

Avec la valeur par défaut PlacedInWorld, un ennemi créé par SpawnActor (une vague, un générateur) n'a aucun contrôleur : il reste planté. Réglez Auto Possess AI sur PlacedInWorldOrSpawned, ou appelez SpawnDefaultController() juste après le spawn.

Se déplacer et regarder

Même sans Behavior Tree, un AIController sait déplacer son Pawn sur le NavMesh avec MoveToActor (suivre un acteur, la destination est mise à jour s'il bouge) ou MoveToLocation (aller à un point fixe). La fin du trajet est signalée par OnMoveCompleted. SetFocus oriente le contrôleur vers un acteur, pour qu'un ennemi garde les yeux rivés sur le joueur même en se déplaçant de côté.

SetFocus ne tourne pas le personnage ?

SetFocus modifie la rotation du contrôleur. Pour que le Character la suive, activez Use Controller Rotation Yaw sur le Pawn, ou Use Controller Desired Rotation dans le Character Movement (en désactivant Orient Rotation to Movement).

La navigation

Pour se déplacer intelligemment, l'IA a besoin de savoir où elle peut marcher. Unreal précalcule pour cela un NavMesh (maillage de navigation) : un ensemble de polygones convexes qui recouvrent les surfaces praticables. Pour aller d'un point à un autre, le moteur cherche une suite de polygones (algorithme A*), puis lisse le trajet en ne gardant que les coins nécessaires.

Générer le NavMesh

  1. Placer un Nav Mesh Bounds VolumePanneau Place Actors → Volumes → Nav Mesh Bounds Volume. Étirez-le pour englober toute la zone où l'IA doit circuler. Un acteur RecastNavMesh-Default apparaît dans l'Outliner : il contient le maillage généré.
  2. Afficher le résultatAppuyez sur P dans le viewport (ou Show → Navigation) : les surfaces praticables s'affichent en vert. Un trou dans le vert est une zone que l'IA ne pourra jamais atteindre.
  3. Régler l'agentProject Settings → Navigation Mesh (ou l'acteur RecastNavMesh) : Agent Radius et Agent Height doivent correspondre à la capsule de vos personnages, Agent Max Slope et Agent Max Step Height aux pentes et marches franchissables.

Le réglage Runtime Generation (Project Settings → Navigation Mesh → Runtime) décide si le NavMesh peut changer en cours de partie :

ModeComportementQuand l'utiliser
StaticCalculé dans l'éditeur, figé en jeuDécor immobile : le moins coûteux
Dynamic Modifiers OnlyMaillage figé, mais les Nav Modifiers peuvent changer les zonesPortes qui s'ouvrent, zones qui deviennent dangereuses
DynamicLes tuiles concernées sont reconstruites quand la géométrie bougeObstacles déplaçables, constructions du joueur, mondes générés

Affiner les déplacements

Nav Modifier Volume
Change la zone (Area Class) d'une région. NavArea_Null la rend infranchissable, NavArea_Obstacle la rend coûteuse (l'IA l'évite si elle peut). Créez vos propres zones en dérivant de UNavArea et en réglant leur DefaultCost : un marécage de coût 5 sera contourné s'il existe un détour moins de 5 fois plus long.
Nav Link Proxy
Relie deux zones séparées du NavMesh : sauter d'un rebord, enjamber un trou. Les deux extrémités se placent dans le viewport, avec un sens (dans les deux sens ou dans un seul). Les Smart Links déclenchent un événement pour jouer une animation de saut.
Navigation Invokers
Pour les très grands mondes : au lieu de tout précalculer, le NavMesh n'est généré qu'autour des acteurs portant un UNavigationInvokerComponent. Nécessite Runtime Generation en Dynamic et l'option Generate Navigation Only Around Navigation Invokers dans Project Settings → Navigation System.

Les Behavior Trees

Un Behavior Tree (arbre de comportement) décrit les décisions de l'IA sous forme d'arbre. Chaque nœud renvoie un résultat (réussite ou échec) à son parent, qui décide quoi faire ensuite. L'exécution part de la racine et parcourt les enfants de gauche à droite, de haut en bas : plus une branche est à gauche, plus elle est prioritaire. Contrairement à un script qui réévalue tout à chaque frame, les Behavior Trees d'Unreal sont événementiels : ils ne réagissent qu'aux changements (une tâche qui se termine, une valeur du Blackboard qui change).

  • RootPoint d'entrée, relié au Blackboard de l'arbre
    • CompositesDécident dans quel ordre exécuter leurs enfants
      • SelectorEssaie ses enfants un par un jusqu'à ce que l'un réussisse (un « OU »)
      • SequenceExécute ses enfants dans l'ordre et s'arrête au premier échec (un « ET »)
      • Simple ParallelUne tâche principale et un sous-arbre exécuté en arrière-plan en même temps
    • TasksLes feuilles : elles agissent (Move To, Wait, Rotate to face BB entry, Run EQS Query, vos tâches)
    • DecoratorsConditions attachées à un nœud (Blackboard, Cooldown, Loop, Time Limit, Is At Location…)
    • ServicesLogique exécutée à intervalle régulier tant que leur branche est active (mettre à jour une distance)

Les observer aborts

Un décorateur Blackboard n'est pas qu'une condition d'entrée : il peut aussi surveiller sa clé et interrompre l'exécution quand elle change. C'est le réglage Observer aborts :

ValeurEffet quand la condition change
NoneRien : la condition n'est testée qu'au moment d'entrer dans la branche
SelfSi la condition devient fausse pendant que cette branche s'exécute, elle est interrompue
Lower PrioritySi la condition devient vraie pendant qu'une branche plus à droite s'exécute, celle-ci est interrompue au profit de cette branche
BothLes deux à la fois

Suivez le scénario sur l'arbre ci-dessus. L'ennemi patrouille et attend 2 secondes (tâche Wait). Le joueur entre dans son champ de vision : la perception écrit TargetActor. Le décorateur de « Poursuivre » observe cette clé avec Lower Priority inclus : la patrouille, moins prioritaire, est immédiatement interrompue et l'ennemi part en chasse sans finir son attente. Plus tard, le joueur se cache et la perception efface TargetActor : grâce à Self (inclus dans Both), la poursuite s'arrête et l'arbre retombe sur la patrouille. Avec None, l'ennemi aurait fini sa pause avant de réagir, puis aurait poursuivi un joueur qu'il ne voit plus jusqu'au bout du trajet.

Une Sequence a trois tâches enfants. La deuxième échoue. Que se passe-t-il ?

  • La troisième tâche s'exécute quand même
  • La Sequence échoue immédiatement, sans exécuter la troisième tâche
  • La Sequence recommence la deuxième tâche jusqu'à ce qu'elle réussisse
  • La Sequence réussit, car la première tâche a réussi

Une Sequence est un « ET » : elle ne réussit que si tous ses enfants réussissent, et s'arrête au premier échec. Son parent (souvent un Selector) passe alors à la branche suivante.

Le Blackboard

Le Blackboard est la mémoire de l'IA : un dictionnaire de clés typées, créé comme un asset (clic droit → Artificial Intelligence → Blackboard) et associé au Behavior Tree. Les tâches, décorateurs et services lisent et écrivent ces clés ; chaque IA possède ses propres valeurs.

CléTypeRôle
TargetActorObject (Base Class : Actor)Le joueur repéré, vide sinon
PatrolLocationVectorProchaine destination de patrouille
LastKnownLocationVectorOù le joueur a été vu pour la dernière fois
IsInAttackRangeBoolÉcrit par le service, lu par le décorateur d'attaque

Le contrôleur et la perception

Il reste à brancher le tout : le contrôleur lance le Behavior Tree quand il possède son Pawn, et un UAIPerceptionComponent lui donne des sens. Chaque sens se configure avec un objet UAISenseConfig_*. Piège courant : l'IA ne voit pas le joueur

Sans système d'équipes, deux acteurs sont considérés comme neutres l'un envers l'autre. Si seul Detect Enemies est coché, rien n'est jamais détecté. Cochez Detect Neutrals (ou configurez les équipes, voir plus bas). Vérifiez aussi que LoseSightRadius est supérieur à SightRadius, et que le joueur ne bloque pas lui-même le canal Visibility avec une collision mal réglée.

Les sources de stimuli et l'ouïe

Pour être vu, un acteur doit être enregistré comme source auprès du système de perception. Par défaut, tous les Pawns le sont automatiquement pour la vue. Pour un acteur qui n'est pas un Pawn (un leurre, un cadavre à découvrir), ou pour contrôler finement les sens concernés, ajoutez-lui un UAIPerceptionStimuliSourceComponent et listez les sens dans Register as Source for Senses.

  • Un service avec un intervalle plus court

Il faut interrompre une branche moins prioritaire (plus à droite) quand la condition devient vraie : c'est Lower Priority. Self n'interrompt que la branche du décorateur elle-même, quand sa condition devient fausse.

EQS : choisir le meilleur endroit

L'Environment Query System répond à des questions spatiales : « où me mettre à couvert ? », « quel point me permet de prendre le joueur à revers ? », « quelle arme au sol est la plus proche ? ». Une requête (asset Environment Query) combine trois étapes :

Generator
Produit des candidats : une grille de points autour de l'IA (Points: Grid), un cercle, un anneau, ou des acteurs d'une classe (Actors Of Class). Les positions sont exprimées par rapport à un contexte (l'IA qui pose la question, le joueur…).
Tests
Évaluent chaque candidat : distance, trace de visibilité (Trace), angle (Dot), chemin existant (Pathfinding), tags… Un test peut filtrer (éliminer les candidats qui échouent) et/ou noter.
Scoring
Les notes de chaque test sont normalisées entre 0 et 1, pondérées et additionnées. La requête renvoie le meilleur candidat (ou un des meilleurs, au hasard, selon le mode choisi).

Dans un Behavior Tree, la tâche Run EQS Query exécute la requête et écrit le résultat dans une clé du Blackboard (un Vector ou un Actor), qu'un Move To peut ensuite utiliser. Pour mettre au point une requête dans l'éditeur, placez un EQSTestingPawn dans le niveau : il affiche en direct les points et leurs scores. Selon votre version du moteur, il peut être nécessaire d'activer l'EQS dans les options expérimentales de l'éditeur (c'était le cas dans UE4).

StateTree : l'alternative moderne

StateTree (plugins StateTree et GameplayStateTree, selon votre version) combine les idées des machines à états et des Behavior Trees. On y définit des états hiérarchiques (Combat contient Attaquer et Se repositionner), chacun exécutant des tâches tant qu'il est actif. Des transitions conditionnelles font passer d'un état à l'autre (sur réussite, échec, événement ou condition), et des évaluateurs (ou tâches globales) calculent des données accessibles à tous les états, à la place du Blackboard. Le tout s'exécute via un StateTreeComponent (ou sa variante pour l'IA) sur le Pawn ou le contrôleur.

Behavior TreeStateTree
ModèleArbre de priorités lu de gauche à droiteMachine à états hiérarchique
MémoireBlackboard (clés nommées)Paramètres et liaisons de propriétés typées
RéactivitéDécorateurs et observer abortsTransitions sur conditions et événements
Logique continueServicesÉvaluateurs, tâches globales
UsagesIA de personnages, très documentéIA, Smart Objects, Mass, logique de jeu générique
MaturitéStable depuis UE4, outils de débogage completsPlus récent, évolue sensiblement à chaque version

Pour apprendre, commencez par les Behavior Trees : la documentation et les exemples sont bien plus nombreux, et les concepts (tâches, conditions, priorités) se transposent directement à StateTree.

Déboguer l'IA

Une IA qui « ne fait rien » est le bug le plus courant, et le plus frustrant sans les bons outils. Unreal en propose trois, complémentaires :

  1. Gameplay DebuggerEn jeu (PIE), appuyez sur la touche apostrophe ' en visant une IA. Un panneau affiche son contrôleur, sa branche de Behavior Tree active, son Blackboard, sa perception et son chemin. Les catégories (NavMesh, AI, Behavior Tree, EQS, Perception) s'activent avec les touches du pavé numérique. Sur un clavier AZERTY, changez la touche dans Project Settings → Gameplay Debugger (Activation Key), ou utilisez la commande console EnableGDT.
  2. Débogueur de Behavior TreeOuvrez l'asset Behavior Tree pendant le PIE : la branche active est surlignée en temps réel et le panneau Blackboard affiche les valeurs. Choisissez l'IA à suivre dans la liste déroulante, et posez des points d'arrêt sur les nœuds (F9).
  3. Visual LoggerTools → Debug → Visual Logger (ou commande VisLog). Il enregistre l'historique de chaque IA : on peut revenir en arrière image par image pour comprendre une décision passée. Vous y ajoutez vos propres traces avec UE_VLOG et UE_VLOG_LOCATION (en-tête VisualLogger/VisualLogger.h).

Les équipes

Pour que la perception distingue amis, ennemis et neutres, les acteurs doivent appartenir à une équipe via l'interface IGenericTeamAgentInterface. AAIController l'implémente déjà : appelez SetGenericTeamId(FGenericTeamId(1)) dans son constructeur. Côté joueur, implémentez l'interface (fonction GetGenericTeamId) sur le PlayerController ou le personnage. Par défaut, deux équipes différentes sont hostiles l'une envers l'autre, et un acteur qui n'implémente pas l'interface est neutre ; surchargez GetTeamAttitudeTowards pour des règles plus fines (alliances, factions).

Vos ennemis apparaissent par vagues via SpawnActor, mais restent immobiles alors que ceux placés à la main dans le niveau fonctionnent. Quelle est la cause la plus probable ?

  • Le NavMesh n'est pas généré à cet endroit
  • Auto Possess AI est resté sur PlacedInWorld : les ennemis spawnés n'ont pas de contrôleur
  • Le Behavior Tree n'a pas de Blackboard
  • La perception ne détecte pas le joueur

Seule la différence « placé / spawné » change entre les deux groupes : c'est exactement ce que contrôle Auto Possess AI. Réglez-le sur PlacedInWorldOrSpawned, ou appelez SpawnDefaultController() après le spawn.

Un garde qui patrouille, poursuit et revient

Créez un garde qui patrouille entre des points placés dans le niveau, dans l'ordre et en boucle. Quand il voit le joueur, il le poursuit ; quand il le perd de vue, il va inspecter le dernier endroit où il l'a vu pendant quelques secondes, puis reprend sa patrouille là où il l'avait laissée. Décrivez le Blackboard et le Behavior Tree, et écrivez le code nécessaire.

Voir la solution

Blackboard : TargetActor (Object/Actor), LastKnownLocation (Vector), PatrolLocation (Vector), PatrolIndex (Int).

Behavior Tree :

  • Selector
    • Sequence « Poursuivre », décorateur Blackboard TargetActor Is Set, Observer aborts : Both → Move To (TargetActor, Acceptable Radius 100).
    • Sequence « Inspecter », décorateur Blackboard LastKnownLocation Is Set, Observer aborts : Lower Priority → Move To (LastKnownLocation) → Wait 3 s → tâche ClearKey qui efface LastKnownLocation.
    • Sequence « Patrouiller » → tâche GetNextPatrolPoint → Move To (PatrolLocation) → Wait 2 s.

La tâche ClearKey est une tâche d'une ligne : OwnerComp.GetBlackboardComponent()->ClearValue(Key.SelectedKeyName), puis Succeeded.

Le contrôleur est exactement AEnemyAIController vu plus haut : la vue écrit TargetActor quand le joueur est vu, l'efface et écrit LastKnownLocation quand il est perdu. La poursuite s'interrompt (Self), l'inspection prend le relais, puis la patrouille reprend quand LastKnownLocation est effacée. Si le garde revoit le joueur pendant l'inspection, la poursuite l'interrompt grâce à Lower Priority.

À retenir

  • Un AIController possède un Pawn comme un joueur ; réglez Auto Possess AI pour les ennemis spawnés.
  • Le NavMesh (Nav Mesh Bounds Volume, touche P) dépend du rayon et de la hauteur de l'agent ; Nav Modifiers et Nav Links l'affinent.
  • Un Behavior Tree se lit de gauche à droite : Selector = « OU », Sequence = « ET ». Les décorateurs avec observer aborts le rendent réactif.
  • Le Blackboard est la mémoire par IA ; ne stockez pas d'état dans les nœuds C++, partagés entre toutes les IA.
  • L'AI Perception configure vue et ouïe ; cochez Detect Neutrals si vous n'avez pas d'équipes, et signalez les bruits avec ReportNoiseEvent.
  • L'EQS choisit des positions (couvert, contournement) ; StateTree est l'alternative moderne aux Behavior Trees.
  • Déboguez avec le Gameplay Debugger, le débogueur de Behavior Tree et le Visual Logger.
